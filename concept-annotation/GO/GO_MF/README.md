This updated set of CRAFT GO_MF concept annotations was created with a newer version of the GO_MF subontology, which is provided within the full Gene Ontology file in this GitHub folder and which we recommend using so as to maximize consistency with these concept annotations.

These annotations are provided in two sets, within the GO_MF and GO_MF_integrated+extended subfolders.  The former exclusively uses proper GO_MF classes for concept annotation, while the latter additionally uses what we call GO_MF extension classes, which are classes we have created for CRAFT GO_MF concept annotation but for which we have specified relationships to proper GO_MF classes.  These are several (not mutually exclusive) rationales for the creation of these extension classes, including (1) semantic integration of semantically equivalent or (textually) indistinguishable classes among two or more of the ontologies used for CRAFT concept annotation; (2) semantic abstraction of one or more GO_MF classes and possibly one or more classes of other ontologies used for CRAFT concept annotation; and (3) annotation of closely related concepts that entail the existence or absence of existence of proper GO_MF classes.  These extension classes are provided within the GO_MF_integrations+extensions.owl ontology file, in which each extension class has been related to one or more proper GO_MF classes with annotation properties subsumed by the superproperty has_related_GO_MF_class.  Note that the GO_MF_integrated+extended annotation set is *not* monotonic relative to the GO_MF annotation set, as some of the annotations made with proper GO_MF classes in the latter are replaced with annotations made with corresponding GO_MF extension classes in the former.

Additionally, most of the GO_MF concept annotations have what we refer to as an interpretation, specifically in the form of FUNCTION-BEARING ENTITY textual attribute values within their XML annotation elements.  These interpretations indicate that the classes used for the annotations should be semantically interpreted as referring to the bearers of the specified function rather than the function itself (e.g., antioxidant for 'antioxidant activity').  These attributes have been created so as to account for this closely related semantic interpretation of these GO_MF classes as used in concept annotations, but implemented so as not to create and maintain large, complex parallel hierarchies of new extension classes mirroring proper GO_MF classes.
