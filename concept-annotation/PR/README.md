This updated set of CRAFT concept annotations was created with a newer version of the Protein Ontology (PR), which is provided in this GitHub folder and which we recommend using so as to maximize consistency with these concept annotations.

These annotations are provided in two sets, within the PR and PR_integrated+extended subfolders.  The former exclusively uses proper PR classes for concept annotation, while the latter additionally uses what we call PR extension classes, which are classes we have created for CRAFT PR concept annotation but for which we have specified relationships to proper PR classes.  These are several (not mutually exclusive) rationales for the creation of these extension classes, including (1) semantic integration of semantically equivalent or (textually) indistinguishable classes among two or more of the ontologies used for CRAFT concept annotation; (2) semantic abstraction of one or more PR classes and possibly one or more classes of other ontologies used for CRAFT concept annotation; and (3) annotation of closely related concepts that entail the existence or absence of existence of proper PR classes.  These extension classes are provided within the PR_integrations+extensions.owl ontology file, in which each extension class has been related to one or more proper PR classes with an annotation properties subsumed by the superproperty has_related_PR_class.  Note that the PR_integrated+extended annotation set is *not* monotonic relative to the PR annotation set, as some of the annotations made with proper PR classes in the latter are replaced with annotations made with corresponding PR extension classes in the former.

Additionally, all of the PR concept annotations have what we refer to as an interpretation, specifically in the form of textual attribute values within their XML annotation elements.  These interpretations indicate that the classes used for the annotations should be semantically interpreted as referring to either gene products or to their corresponding genes.  These have been created so as to account for the complexity of several possible related semantic interpretations of these PR classes as used in concept annotations, but implemented so as not to create and maintain large, complex parallel hierarchies of new extension classes mirroring proper PR classes.
